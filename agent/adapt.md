# Agent Skill：ADAPT

## 目标
针对 MFTR0 / HyperOS TV 固件差异做可重复适配，而不是在代码里堆未经验证的机型特判。

## 流程
1. 读取 `docs/DEVICE-MFTR0.md` 和 Aerial 同型号设备笔记。
2. 采集当前设备指纹、固件版本、包存在性、系统设置项和行为。
3. 优先使用功能检测（包是否存在、设置项是否存在、API 能力是否可用）；只有无法检测时才按型号/Build fingerprint 选择 DeviceProfile。
4. 对每个候选开关：记录原值 → 用户批准 → 单变量修改 → 读回 → 真机验证 → 保留或回滚。
5. 任何无效开关必须恢复原值。
6. Aerial 的通知监听复活、GuardSetup 重绑、有限延迟检查可作为设计参考；不要照搬桌面接管或按键过滤。
7. 不得停用 PatchWall，不得自动修改 HOME role，不得清理用户应用。
8. 真机验证必须使用实体遥控器；ADB keyevent 只作为辅助测试。

## 产出
更新设备档案，说明适用固件、证据、成功率（若样本不足则不估算）、副作用、回滚方式和未验证范围。
